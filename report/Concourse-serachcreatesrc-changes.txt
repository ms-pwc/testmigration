SearchCreateSrc Workflow - Changes Made for Successful Run
===========================================================

1. Azure Login Step missing - Added for the first step (only one place missing)
   - Azure Login (OIDC) step is present at start of each job

2. Variable Groups Loading - Made Dynamic 
   - Changed from: groups_to_load = ['search-${{ inputs.ENVIRONMENT }}']
   - Changed to: Dynamic lookup that finds any group ending with "::search-{environment}"
   - Added INPUT_ENVIRONMENT env variable in load step to pass environment input to Python
   - definetly need project based filtering

4. Azure PowerShell Task Format - Fixed for GitHub Actions
   - Changed invalid input names:
     * ScriptType -> removed
     * Inline -> inlineScript
     * azureSubscription -> removed (not needed with prior login step)
     * azurePowerShellVersion -> azPSVersion (changed to 'latest')
   - Applied to all three Configure steps: DataSource, SearchIndex, SearchIndexer

5. Environment Variable References - Fixed in PowerShell Scripts
   - Changed from: ${{ env.SEARCHAPI }}  (workflow context)
   - Changed to: $env:SearchApi  (runtime environment variable)
   - Why: Variables loaded in prior bash step are only available at runtime as $env: in PowerShell

6. Working Directory Path - Updated for GitHub Actions
   - Changed from: $env:BUILD_SOURCESDIRECTORY  (Azure Pipelines)
   - Changed to: $env:GITHUB_WORKSPACE  (GitHub Actions standard)
   - Why: GitHub Actions uses GITHUB_WORKSPACE to point to checked-out repo

7. Step Naming - Removed Azure DevOps Syntax
   - Changed from: "Azure Login - $(Azure_Subscription)"
   - Changed to: "Azure Login (OIDC)" or similar
   - Why: $(variable) syntax is ADO-specific, not GitHub syntax

8. Environment Variable Casing - Aligned Names
   - Declared at top: Azure_Subscription (with underscore)
   - Used in steps: env.Azure_Subscription (matching the declared name)
   - Note: Case-sensitive in shell, be precise with variable names
