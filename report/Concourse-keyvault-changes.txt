POINT 1: Fix Task Name and Variables/Operation
====================================================

Current Issue in test.yml:
- Task name uses: name: ${{ variables.operation }} Secret
- This references undefined 'variables.operation' - GitHub has no 'variables.' context in this way.
- Variables defined in env block use wrong casing: OPERATION, KEYVAULT, SECRETNAME, SECRETVALUE

Change Required:
- Replace task name to: name: "${{ inputs.Operation || 'List' }} Secret"
- Use inputs directly in the condition, not env variables
- Keep references consistent: inputs.Operation, inputs.KeyVault, inputs.SecretName, inputs.SecretValue
- Remove env variables block that defines operation, azureSub, keyVault, secretName, secretValue

Working Pattern:
  name: "${{ inputs.Operation || 'List' }} Secret"
  env:
    KEYVAULT_NAME: "${{ inputs.KeyVault || 'test-keyvault-git-001' }}"
    SECRET_NAME: "${{ inputs.SecretName || '' }}"
    SECRET_VALUE: "${{ inputs.SecretValue || '' }}"
    OPERATION: "${{ inputs.Operation || 'List' }}"

POINT 2: Add Azure Login Task (Missing Step)
====================================================

Current Issue in test.yml:
- No azure/login@v2 step present before the keyvault operation step
- This means no Azure authentication happens, so all keyvault commands will fail

Add After Step: "Checkout code"

  - name: Resolve Azure credentials from selected service connection
    id: resolve_azure
    shell: bash
    run: |
      case "${{ inputs.AZURESUB || 'concoursesearch-dev-connection' }}" in
        "concoursesearch-dev-connection")
          echo "client_id=${{ vars.AZURE_CLIENT_ID_CONCOURSESEARCH_DEV_CONNECTION }}" >> "$GITHUB_OUTPUT"
          echo "tenant_id=${{ vars.AZURE_TENANT_ID_CONCOURSESEARCH_DEV_CONNECTION }}" >> "$GITHUB_OUTPUT"
          echo "subscription_id=${{ vars.AZURE_SUBSCRIPTION_ID_CONCOURSESEARCH_DEV_CONNECTION }}" >> "$GITHUB_OUTPUT"
          ;;
        [additional cases for other subscriptions...]
      esac

  - name: Azure Login (OIDC)
    uses: azure/login@v2
    with:
      client-id: "${{ steps.resolve_azure.outputs.client_id }}"
      tenant-id: "${{ steps.resolve_azure.outputs.tenant_id }}"
      subscription-id: "${{ steps.resolve_azure.outputs.subscription_id }}"
